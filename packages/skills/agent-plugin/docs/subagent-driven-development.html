subagent-driven development

Model eksekusi default untuk pekerjaan multi-unit: section Figma, frame, task code, refactor, Flutter, atau Vue. Orchestrator memegang state tipis di file; worker mendapat konteks baru per unit; hasil berupa report file; gate dijalankan pihak luar.

Route contractWRAPPER · ANY CALLER
BagianAs-is
TriggerCaller punya lebih dari satu unit, multi-frame/section, atau risiko context window penuh.
PrasyaratCaller sudah menentukan unit, writable set, brief fields, dan gate. Skill ini tidak menentukan isi task.
MemanggilDipakai di atas Flutter, Vue, atau code plan; worker mengikuti caller skill.

Kapan aktifdefault, bukan opt-in
  • Unit > 1, atau satu pekerjaan berisiko memenuhi context window.
  • Caller menentukan unit dan gate; skill ini menentukan brief, isolation, report, verification, resume.
  • Dengan subagent tool: satu worker per unit. Tanpa tool: sequential fallback, reset context setelah report.

Core rules

1Brief sebelum dispatch

Brief wajib memuat goal, absolute input paths/node ids/URL, writable set, rules yang harus dibaca, definition of done, dan report path. Brief tidak lengkap berarti unit belum ready.

2Fresh context dan file report

Worker hanya menerima path brief plus skill yang diikuti. Heavy Figma output, screenshot, dan log tinggal di worker. Worker menulis report, lalu mengembalikan satu status line; orchestrator membaca file, bukan transcript.

3Disjoint write sets

Parallel hanya jika writable set tidak overlap. Registry, plan.md, pubspec.yaml/package.json, main.dart/router, dan shared assets punya satu writer: orchestrator. Maksimal 3–4 worker paralel; ragu → serial.

4External verification

Worker tidak boleh certify gate sendiri. Bukti berupa script exit code, test/analyze/lint, file existence, validator --check, atau verifier terpisah. Visual gate memakai score geometry lalu pixel diff; verifier fresh menjelaskan diff, score yang menentukan.

5Human gate tetap human

Pertanyaan developer direlay orchestrator, tidak dijawab sendiri. Gunakan structured question tool jika ada. Simpan jawaban verbatim di brief/report.

6Retry rules

Unit gagal gate dua kali → BLOCKED, bukan retry tanpa akhir. Score gate yang mengukur progress memakai aturan fidelity sendiri: tidak ada round cap sampai pass atau stop menjadi NEEDS_CONTEXT. Jangan re-dispatch brief identik.

7Tidak ada mode question

Linear vs parallel ditentukan jumlah unit dan write set, bukan ditanyakan ke developer. Catat keputusan di progress.md.

Workspace

.sdd/<batch-id>/
├── progress.md          # satu row per unit; orchestrator-only
├── tasks/<unit-id>.md   # brief sebelum dispatch
└── reports/<unit-id>.md # worker report

Status: pending → running → awaiting-verify → awaiting-human → done/gated, atau needs-context/blocked. Hapus workspace saat semua unit done atau gated dengan acknowledgment. Permanent result masuk project files.
