flutter-match-component

Mencocokkan node Figma ke komponen Flutter BUMA Design System yang tepat, termasuk constructor lengkap, variant, state, props, token, dan instance child. Dipakai mandiri atau sebagai langkah resolusi komponen di flutter-slice-screen.

Langkah

1Ambil konteks, bukan tebakan

Panggil get_design_context pada node terlebih dahulu. Response sparse berarti panggil ulang pada semua child yang terlihat dalam satu batch paralel; prompt koneksi Code Connect bukan data dan tidak boleh memicu mapping baru. Jangan memanggil get_code_connect_suggestions, send_code_connect_mappings, atau add_code_connect_map.

2Wrapper Component/ wajib turun ke Inner

  1. Ambil compound id Inner dari get_metadata: I<outerId>;<innerId>.
  2. Panggil get_design_context pada compound id. get_code_connect_map tidak menerima compound id.
  3. Jika kosong atau bukan Flutter, cari file library Inner lalu panggil mapping/context dengan plain Inner id.
  4. Terima hanya hasil berlabel Flutter. Simpan catatan: Inner I<outer>;<inner> <name> → <Flutter class> ✓ Flutter (inner).
  5. Terapkan nilai instance wrapper ke Inner. Default master tidak boleh menimpa variant instance.

Inner belum ter-resolve berarti BLOCKED/NEEDS_CONTEXT; jangan turun ke rung lain.

3Escalation ladder

  1. Code Connect: baca contoh lengkap dan komentar load-bearing; ganti semua data contoh dengan nilai node aktual.
  2. Metadata/API: baca component.meta.yaml, atau folder public component pada checkout resolved. Catat sebagai inferred.
  3. Existing usage: hanya compatibility fallback.
  4. Local: presentation/widgets/<screen>_<widget>.dart; catat hasil Code Connect dan gap. Jangan membuat komponen di package DS.

Berhenti pada match pertama. Jangan memakai checkout DS yang lebih baru daripada package target.

4Rekonsiliasi tiga evidence

Inner mapping / metadata = identitas + constructor
placed Figma instance       = label, content, variant, state, value
variables + geometry        = token, visual, posisi, ukuran

Ketahui setiap label, value, selected index, icon, state, axis, fill/hug, spacing, radius, stroke, shadow. Nilai wajib yang tidak diketahui = BLOCKED/NEEDS_CONTEXT, bukan literal contoh atau default DS.

5Constructor lengkap dan gotcha

Code Connect props adalah subset. Baca constructor penuh dari component.meta.yaml atau source, lalu baca references/gotchas.md. Flag prop sizing, overflow, alignment, effect: isHugging, fillWidth, isScrollable, wrap, expand, stretch, tabAlignment, crossAxisAlignment, hasShadow, hasBorder, hasElevation. Setiap nilai non-default punya bukti Figma.

Placeholder seperti Option 1, Label, Tab, Home dianggap unresolved kecuali Figma memang menampilkannya.

6Floating dan placement

Scaffold.floatingActionButton hanya jika semua fakta terpenuhi: node sibling root di luar scrollable subtree; bounds overlap atau tepat di atas fixed chrome; stacking terbukti; node memiliki shadow/elevation sendiri. Location mengikuti anchor. Satu fakta hilang → inline composition normal.

7Per-instance dan per-child

  • Setiap instance mengulang resolusi props dari node sendiri; jangan reuse antar instance.
  • Turun ke nested child instance sampai level terakhir. Parent mapping tidak mencakup badge, icon, label, atau action.
  • Identitas exact dari Inner, bukan kemiripan: UITabSwitch dan UISegmentedSwitch tetap berbeda.
  • Style node dan descendant diselesaikan dari tokens.md; komponen tanpa prop yang dibutuhkan = gap.
  • Tidak ada raw Material button atau Colors.* jika DS menyediakan padanan.

Aturan penolakan match

Bukti wajib

Match rung 1–2 hanya boleh dibuang dengan dependency nyata yang terverifikasi, bukan karena posisi umum atau asumsi interface. Contoh dependency: parameter hanya tersedia dari ancestor, atau DefaultTabController.of(context) melempar tanpa ancestor. Catat ⚠ DS match discarded: dengan nama komponen dan requirement yang gagal.
