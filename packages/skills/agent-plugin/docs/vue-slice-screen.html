vue-slice-screen

Mengubah frame/node Figma yang approved menjadi screen Vue runnable, presentation-only, dengan BUMA Design System. Flow aktif hanya untuk app standalone; shell atau remote Module Federation berhenti untuk keputusan developer.

Route contractSTART · DIRECT · CALLED BY ROUTER
BagianAs-is
TriggerDirect: node Figma + target Vue standalone. E2E: router sudah menyelesaikan intent/design. Multi-frame: orchestrator memilih skill ini per frame.
PrasyaratURL node, screen name, feature directory, routing mode; Vue scaffold dan BUMA packages dibuat/dicek di awal flow.
Memanggilvue-resolve-assets untuk non-icon assets; SDD untuk multi-frame/heavy; tidak memanggil Flutter skills.
Outputplan.md, Coverage/CM/AS decisions, human approval verbatim, section .vue, spec.md.

  • Routing mode: none, suggest, atau auto; default suggest.

Langkah

1Check scaffold

Temukan nearest package.json. Standalone harus punya Vue, app entry, bundler, usable src/, dan router sendiri. Jika ada federationConfig.ts, remotes, atau exposes, flow aktif berhenti; jangan memperbaiki shell/remote. Jika scaffold absent/incomplete, gunakan references/scaffold-standalone.md untuk setup self-contained tanpa federation.

2BUMA package dan integrasi

  • Resolve UI-kit aktual dan @buma-dev/styles di disk; jangan campur major v1/v2.
  • Install hanya package yang hilang memakai package manager repo. Jangan menambah auth, layout, state, API, chart, atau federation dependency.
  • Stylesheet public dan plugin UI kit di-import sekali di main.ts; komponen memakai global B<Name>, tanpa deep imports.
  • SCSS token di-wire sekali lewat bundler additionalData, bukan import tiap screen. Catat check 1, 3, 5 di plan.md.

3Safety sebelum Figma

Pastikan file target tidak konflik. Jangan overwrite/restructure file existing tanpa otorisasi. Pastikan Figma MCP tersedia; jangan install MCP atau ubah editor-global config diam-diam.

4Branch node dan complexity

Panggil get_metadata sebelum Figma call lain. Single FRAME/COMPONENT/INSTANCE lanjut. PAGE/CANVAS/SECTION dengan beberapa independent FRAME → baca orchestration, satu frame worker per screen, fresh context. Heavy single frame boleh memakai SDD; gate tetap sama. Ambiguous → tanya developer sekali dengan candidate frames. Enumerate setiap layer, group, vector, text, nested frame, pada seluruh depth; re-fetch component/instance berisi lebih dari leaf sederhana. Catat complexity light/medium/heavy sebelum get_screenshot/get_design_context; satu heavy call pada satu waktu.

5Inventory dan plan.md

Group direct children sesuai sibling order; satu section per child. Baca references/output-contract.md, reuse atau alokasikan specs/<ID>-<screen-name>/. Tulis plan.md sekarang, sebelum resolution, dengan:

  • Environment checks.
  • Inventory lengkap dan tidak difilter.
  • Coverage, Component, Asset, Routing, Progress kosong.
  • Files to create: thin screen, Content, dan satu <ScreenName><SectionName>.vue per direct-child section.

6Resolve section per section

  1. Panggil get_code_connect_map per node dulu. Jika ada mapping repo, pakai langsung.
  2. Panggil get_variable_defs; resolve color/spacing/radius/typography dari variable sebelum numeric fallback.
  3. Tanpa mapping, panggil get_design_context section-level; cocokkan global B<Name> atau screen-local. Baca component.meta.yaml sebelum source component.
  4. Placeholder text seperti Label, Title, Lorem ipsum, empty → re-fetch leaf text node. Kalau tetap placeholder, tulis gap; jangan ship copy itu.
  5. Visible text wajib punya Color dan Typography row; non-text menulis n/a, bukan cell kosong.
  6. Setiap node inventory punya Coverage row: CM-XX, AS-XX, native-layout, grouped, atau gap beralasan. Tulis langsung ke plan sebelum section berikutnya.

7Assets dan unsupported visuals

Image/illustration non-icon memakai vue-resolve-assets. Icon kecil masuk Code Connect/UI kit/repo convention; jangan font icon tebakan. Chart, map, animation tanpa UI-kit equivalent atau existing project usage menjadi gap; jangan menambah dependency unilateral.

8Mechanical check pertama

Setelah semua section ter-resolve, pastikan Coverage punya tepat satu row per Inventory entry. Jalankan:

<skill-dir>/scripts/validate-slice.sh <plan.md> <vue-dir> [repo-root]

Pada step 14 .vue belum ada, jadi directory-missing adalah expected; semua finding plan tetap harus diperbaiki. Jangan menulis .vue sebelum check ini.

9Human gate — tidak boleh dijawab sendiri

Step 15

Stop. Minta konfirmasi developer eksplisit dengan structured question tool. Ringkas state, components, assets, routing, dan setiap CM-XX yang menjadi screen-local karena tidak ada UI-kit match. Jangan menulis .vue sebelum approved. Simpan jawaban developer verbatim di checklist plan.

10Generate

Generate tepat file yang tercantum di Files to create. Setiap direct-child section wajib file sendiri; <ScreenName>Content.vue hanya compose section. Presentation-only: state loading/empty/content/error hanya jika Figma atau user meminta. Check Progress live.

11Routing

Untuk mode selain none, baca references/routing.md, implementasikan sesuai mode, dan check item routing di plan. Jangan menyentuh route file shared pada worker orchestration; orchestrator satu-satunya writer.

12Fresh verify

Re-call get_metadata fresh, cocokkan seluruh entry dengan Coverage. Cek text verbatim, props/variant, flex direction, spacing/radius token dari row plan, lalu jalankan validator lagi. Negative margin gagal kecuali Coverage membuktikan overlap Figma. Placeholder copy gagal kecuali developer mengonfirmasi string nyata. Setiap <img> wajib alt; icon-only control wajib accessible name.

Jalankan dev server dan visual compare dengan get_screenshot pada viewport nyata. Simpan screenshot atau outcome di Progress. Jika screenshot gagal, retry; fallback numeric cross-check fresh metadata harus dicatat eksplisit.

13Lint dan finalize

Jalankan repo lint/format hanya pada changed files. Finalize specs/<ID>-<screen-name>/spec.md dari output aktual: AC, CM, AS, routing, dan validation outcome.

Heavy-call policy

ClassAturan
lightFrame kecil; call normal, tetap inventory lengkap.
mediumSection menjadi heavy-call boundary; satu heavy call aktif.
heavyGunakan SDD bila perlu; bounded retry, circuit breaker, numeric fallback eksplisit.
multi-frameOrchestrator; worker fresh per frame; shared files hanya orchestrator.
Batasan
  • Tidak membuat store, business composable, API/service, route guard/middleware.
  • Preview data hanya local const di content component; tidak invent API data.
  • Prefer global BUMA B<Name>; jangan membuat component di package UI kit.
  • Standalone only pada flow aktif; federation config = stop dan minta keputusan.
  • Jangan menambah dependency chart/map/animation.
  • Di luar feature hanya route file yang explicitly diizinkan oleh routing mode.
  • Pixel-perfect tidak boleh diklaim tanpa rendered/visual verification.
