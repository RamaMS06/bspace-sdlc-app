flutter-slice-screen

Skill utama Flutter. Mengubah node Figma menjadi screen Flutter yang bisa dijalankan, khusus kode presentation, dengan BUMA Design System. Dipakai untuk screen baru, menambah satu komponen ke screen yang sudah ada, memperbaiki props/sizing/styling agar sesuai Figma, atau memperbaiki mismatch Code Connect. Tidak dipakai untuk API, domain, atau repository, dan tidak untuk web/Vue.

Input dan prinsipSKILL.md · references/ (11) · scripts/ (4) · assets/
  • Input: URL node Figma. Opsional: --intent intent/<ID>/intent.md dari using-bspace-sdlc.
  • Hanya satu pertanyaan, sekali: nama epic. Nilai lain (nama screen, folder, route, package, section) memakai default deterministik dan dicatat di plan.md.
  • Selalu orchestrator dan worker (subagent-driven-development): sesi ini tidak pernah memegang payload Figma milik section. Setiap section dikerjakan worker dengan konteks baru, termasuk screen yang hanya punya satu section.
  • Import DS hanya lewat barrel: import 'package:buma_design_system/buma_design_system.dart';. Tidak pernah src/.
  • Hemat token: response Figma tidak pernah diketik ulang (pakai figma_xml.py raw), setiap node di-fetch sekali, PNG tidak dibaca di luar perbandingan render, warna diambil dari get_variable_defs dan bukan dari piksel, plan.md dibaca per heading lewat grep.

Langkah

1–2Screening dan harness

references/project-screening.md dijalankan sekali. SDK Flutter di-pin ke .fvmrc milik DS (environment.md §0). buma_design_system wajib ada: kalau belum, ditambahkan dengan URL git tetap dan ref: release. resolved-ref dari pubspec.lock dicatat di ## Notes.

3Folder slice

python3 <skill-dir>/scripts/validate_output.py --init <screen_name> --epic <epic-slug> <package-root>/specs/

Exit 3 berarti nama screen ini adalah prefix dari slice lain. Developer ditanya sekali: section dari screen itu, atau screen baru (--new)?

4Membaca node

  • Response get_metadata disimpan verbatim (fence ```xml) lewat figma_xml.py raw lalu extract. --check menolak tag karangan dan node tanpa geometri.
  • Evidence: setiap nilai yang tidak bisa dibuktikan render (data, perilaku tap/drag, pilihan variant) menjadi baris ## Evidence berisi node id dan field. Kalau tidak ada sumber, statusnya NEEDS_CONTEXT, tidak ditebak.
  • Layout dari CSS get_design_context: flex-row → Row, flex-1 → Expanded, tanpa class ukuran → hug. Tinggi ditentukan oleh konten. Di layar sempit, layout reflow dan tidak pernah dikecilkan. Teks tidak pernah dipotong kecuali node Figma-nya punya truncate. Geometri dibulatkan ke integer.

5Resolusi

Komponen ke flutter-match-component, aset ke flutter-resolve-assets. Setiap warna, font, spacing, dan radius adalah token DS. Chart: chart DS dulu, kalau tidak ada pakai fl_chart; Syncfusion hanya untuk radial atau gauge. Tipe chart ditentukan dari bentuknya, bukan nama layer.

6spec.md dan plan.md

spec.md hanya berisi WHAT: tujuan, state, AC. plan.md berisi empat bagian: Sections (Node | Name | Widget file), Assets (Node | Name | Kind | Path), Evidence (Property | Value | Source), dan Notes (target, DS, harness, baris mask/reference/chart, serta run:). Hanya orchestrator yang menulis plan.md.

7Generate Dart

File screen memegang chrome (Scaffold, appBar, bottomBar, FAB), content widget memegang body. Teks memakai UILabel, bukan Text(. Alpha diatur lewat token, bukan Opacity(. Setiap section punya file sendiri. Kode dibangun dari snippet Code Connect dengan nilai instance yang sebenarnya.

8Fidelity dan --check

Per section, lihat flutter-verify-fidelity. Setelah semua section pass, orchestrator menjalankan:

python3 <skill-dir>/scripts/validate_output.py --check <target-feature-directory>

--check gagal pada: literal hardcoded (warna, TextStyle(, EdgeInsets), Icon( atau tombol Material mentah, Opacity(, Text(, render yang hilang atau basi, section yang tidak lulus skor ulang, aset yang tidak ada atau tidak dideklarasikan, harness tidak di-copy verbatim, frameWidth yang tidak sama dengan Figma, report worker yang belum DONE, SDK di luar pin, intent AC yang belum dipetakan atau pin basi, dan run: BLOCKED. Maksimal dua ronde, lalu berhenti dan melapor.

9Verifikasi headless dan device

flutter-run-verify: PASS (headless), lalu satu kali run di device per batch. Setelah itu rekonsiliasi spec.md (AC met atau diverged) dan git add folder slice.

Script

validate_output.py

--init membuat folder slice. --check adalah gate kode, yang juga menjalankan ulang skor setiap section dan mengecek pin intent.

figma_xml.py

raw · extract · spec · assets · classify: menyalin response Figma dari transcript, memotong subtree, membuat spec section, mengunduh aset, dan mengklasifikasi chart.

diff_renders.py

Skor render: geometri vs metadata, lalu diff piksel YIQ. Exit 0/1/4/5. Lihat flutter-verify-fidelity.

chart_refs.py

Mencetak kode chart yang versinya pas dari source dan test chart DS serta example/ package yang ter-resolve.

Self-check: python3 scripts/check_plan_tables_selfcheck.py. Asset: assets/test-support/fidelity_harness.dart (loadDsFonts, pumpDs, writeLayout) dan assets/screen-template/.

Batasan
  • Hanya presentation: tidak ada domain, repository, datasource, service, API client, atau serialization.
  • Tidak pernah membuat komponen di dalam package DS. Kalau tidak ada yang cocok, dibuat widget lokal screen dan gap-nya dicatat.
  • Di luar fitur target, yang boleh disentuh hanya: route registry (mode auto), main.dart/pubspec.yaml untuk harness, dan dependency DS.
  • Figma dan Code Connect read-only: tidak memanggil get_code_connect_suggestions, send_code_connect_mappings, atau add_code_connect_map.
  • Report worker BLOCKED atau NEEDS_CONTEXT menghentikan slice: tidak ada route dan tidak ada run.
