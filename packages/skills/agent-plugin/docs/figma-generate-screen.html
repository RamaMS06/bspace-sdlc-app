figma-generate-screen

Generate screen apa pun di Figma dengan BUMA Design System. Bisa dipanggil langsung oleh designer (dengan atau tanpa FSD), atau oleh router using-bspace-sdlc sebagai fase P3 Design. Gate sama di dua mode; yang beda hanya sumber input.

BagianAs-is
Trigger"Buat screen di Figma", "generate design", atau router sampai di P3 Design.
PrasyaratAkses Figma (remote MCP untuk write), designer yang menjawab D0. FSD tidak wajib saat mandiri.
MemanggilSkill Figma figma-use + figma-generate-design; aturan BUMA di references/figma-libraries.md menang.
Outputdesign.md, design-evidence/, frame Figma di lokasi pilihan designer.
NextMode SDLC: kembali ke router (FTSD). Mandiri: URL node ke flutter-slice-screen / vue-slice-screen.

Tidak adaBrief singkat ke designer → ## Screen Brief + Brief-approved-bybrief SCR-xx

Brief: tujuan screen, user, platform (mobile 393 / web), data & field, aksi dan tujuannya, state (loading, empty, error, disabled, success), do/don't. Jadi skill ini bisa untuk screen apa pun.

Lokasi file: project SDLC → intent/<ID>-<slug>/design.md; mandiri → design/<slug>/design.md (atau folder pilihan user).

D0 — referensi + lokasi (selalu tanya designer)

  1. Referensi per screen: frame mana yang diikuti, apa yang diambil, apa yang dihindari. Inspirasi luar (Pinterest, Dribbble) cukup URL + catatan, tidak di-fetch.
  2. Target file: URL figma.com/design/<fileKey>/….
  3. Target page: URL page yang sudah ada, atau nama page baru dari designer. Tidak ada page default; AI tidak membuat/memilih page sendiri.
  4. Placement: di samping frame X (URL node), di dalam section Y, atau section baru.
Target-file: https://www.figma.com/design/AbC.../Attendance
Target-page: https://www.figma.com/design/AbC.../Attendance?node-id=0-1

AI hanya membuka URL dari brief dan catalog, jadi hemat token. Revisi normal: ubah baris, tanggal ulang, inspeksi hanya REF yang berubah.
